## 1. 项目名称

晨枢 AI

## 2. 项目类型

个人 AI 工作台 / 多智能体内容与研究生产平台。

项目初期以个人自用为核心，优先解决高频、复杂、重复的信息处理与内容生产任务；中后期逐步沉淀为可上线的 SaaS 化或私有化部署产品。

## 3. 项目背景

当前个人在学习、研究、创作、投资分析、编程实验和职业发展中，会频繁遇到以下问题：

1. 任务类型多，工具分散。
   简历修改、模拟面试、论文写作、专利撰写、小说创作、剧本创作、歌词创作、社媒内容生产、代码实验、信息搜集、论文追踪、股票分析等任务通常依赖不同网站、不同软件和不同工作流，切换成本较高。

2. 大模型能力强，但缺少稳定的个人工作流。
   单次对话可以完成局部任务，但缺少任务模板、文件管理、上下文沉淀、历史版本、自动化计划、定时汇报和多步骤执行能力。

3. 信息搜集与汇总高度重复。
   每天查看 arXiv 最新论文、不同网站资讯、股票信息、行业动态等任务具有明显的周期性，适合通过自动化代理完成。

4. 本地模型与云端 API 各有优势。
   云端 API 在能力、稳定性和多模态方面更强；本地模型在隐私、成本、可控性、离线使用和可微调方面更有潜力。项目需要从一开始预留“云端 API + 本地模型 + 混合调度”的架构空间。

5. 后期存在产品化可能。
   如果个人使用效果稳定，可以围绕特定人群和场景上线，例如学生、研究者、内容创作者、求职者、独立开发者、投资研究者等。

## 4. 项目愿景

构建一个面向个人知识工作者的 AI 中枢平台，让用户可以用统一入口完成创作、研究、分析、编程、面试、信息监控和自动化汇报等任务。

晨枢 AI 的长期目标不是做一个简单聊天工具，而是做一个“可调用工具、可管理任务、可沉淀知识、可自动运行、可扩展模型”的个人 AI 操作系统雏形。

## 5. 项目目标

### 5.1 短期目标

完成一个个人可用的 Web 平台，支持通过 API 调用大模型，并围绕高频场景提供结构化工作流。

短期重点包括：

- 简历分析、模拟面试、面试反馈和简历修改建议。
- 论文、专利、小说、剧本、歌词、社媒推文等内容生成。
- 代码生成、实验脚本辅助、实验结果解释和报告整理。
- 指定网站信息自动搜集、摘要、对比和汇总报告。
- arXiv 每日指定方向论文自动搜集与汇总。
- 股票信息自动搜集、基础分析和预测辅助。

### 5.2 中期目标

形成稳定的任务系统和知识库能力，使平台能够管理长期任务、定时任务、文件上下文和历史产出。

中期重点包括：

- 支持多种任务模板和可配置工作流。
- 支持文档上传、解析、版本管理和知识库检索。
- 支持定时自动任务，例如每日论文简报、股票信息日报、行业信息周报。
- 支持工具调用，例如网页搜索、网页抓取、代码执行、文件读写、表格生成、图表生成。
- 支持多模型配置，允许不同任务选择不同模型。

### 5.3 长期目标

探索本地模型部署、模型微调和产品上线。

长期重点包括：

- 接入本地大模型或本地小模型。
- 形成“本地小模型处理低成本任务 + 云端 API 处理复杂任务”的混合方案。
- 探索基于个人语料、写作风格、面试题库、研究方向资料的微调或 RAG 方案。
- 完成用户体系、权限体系、计费体系和部署体系。
- 将平台从个人自用工具升级为可对外发布的产品。

## 6. 目标用户

### 6.1 第一阶段用户

项目创建者本人。

主要特征：

- 有大量写作、研究、学习、实验和信息分析需求。
- 愿意折腾技术方案。
- 接受早期产品不完美，但要求结果真实可用。
- 更关注效率提升和工作流闭环，而不是界面精美程度。

### 6.2 后期潜在用户

后期可扩展到以下用户群体：

- 求职者：需要简历优化、模拟面试、岗位匹配和面试复盘。
- 学生与研究者：需要论文追踪、论文阅读、论文写作、实验代码和研究汇报。
- 内容创作者：需要小说、剧本、歌词、公众号、小红书、知乎等内容生产。
- 独立开发者：需要代码生成、实验运行、技术方案分析和自动文档。
- 投资研究者：需要股票数据搜集、资讯汇总、公司分析和趋势跟踪。
- 小团队：需要内部知识库、自动报告和多角色 AI 助手。

## 7. 核心使用场景

### 7.1 简历与模拟面试

用户上传简历，选择目标岗位或输入岗位 JD，系统自动完成：

- 简历结构分析。
- 经历亮点提取。
- 简历问题诊断。
- 简历修改建议。
- 模拟面试问题生成。
- 分轮次模拟面试。
- 回答质量评价。
- 面试复盘报告。
- 针对岗位的补强建议。

### 7.2 学术论文与专利写作

用户输入研究主题、已有资料、论文结构或专利方向，系统辅助完成：

- 选题分析。
- 文献综述草稿。
- 论文大纲。
- 摘要、引言、方法、实验、结论等章节草稿。
- 专利交底书。
- 权利要求书初稿。
- 技术方案描述。
- 创新点梳理。
- 语言润色与格式调整。

说明：该模块输出内容应定位为辅助草稿和结构建议，最终学术真实性、数据真实性、专利法律有效性需要用户自行审核或交由专业人士确认。

### 7.3 创意写作

支持小说、剧本、歌词等创作任务。

核心能力包括：

- 世界观设定。
- 人物设定。
- 故事情节设计。
- 分章节大纲。
- 正文续写。
- 对话润色。
- 剧本分场。
- 歌词主题、段落、押韵和风格生成。
- 多版本改写。

### 7.4 新媒体内容生产

支持小红书、知乎、公众号推文等平台内容。

核心能力包括：

- 选题生成。
- 标题生成。
- 内容大纲。
- 正文撰写。
- 平台风格改写。
- 标签和关键词建议。
- 爆款结构拆解。
- 多平台一稿多改。

### 7.5 代码与实验

面向学习、研究和开发实验，支持：

- 根据需求生成代码。
- 解释代码。
- 调试报错。
- 生成实验脚本。
- 运行实验并汇总结果。
- 生成图表。
- 整理实验记录。
- 生成技术报告。

该模块后续可与本地沙箱、Notebook、容器或远程服务器结合。

### 7.6 网站信息搜集与汇总

用户配置目标网站、关键词、频率和输出格式，系统自动完成：

- 网页访问。
- 信息抽取。
- 去重。
- 摘要。
- 分类。
- 对比。
- 趋势汇总。
- 生成日报、周报或专题报告。

### 7.7 arXiv 每日论文追踪

用户配置研究方向、关键词、作者、分类或机构，系统每日自动完成：

- 拉取 arXiv 最新论文。
- 按相关性筛选。
- 生成中文摘要。
- 提取方法、贡献、实验和结论。
- 标记值得精读的论文。
- 生成每日论文简报。
- 保存历史记录，支持后续检索。

### 7.8 股票信息搜集与分析

用户配置股票池或关注行业，系统自动完成：

- 股票价格和行情数据搜集。
- 公司公告和新闻搜集。
- 财务指标整理。
- 走势和事件摘要。
- 风险点提示。
- 生成分析报告。
- 给出趋势判断和预测辅助。

说明：该模块仅作为研究和辅助分析工具，不提供确定性投资建议，不承诺收益，需要在产品中明确风险提示。

## 8. 产品定位

晨枢 AI 的定位是“个人 AI 任务中枢”，不是单一写作工具、单一搜索工具或单一聊天机器人。

核心差异点：

- 以任务为中心，而不是以聊天为中心。
- 以个人长期工作流为中心，而不是一次性问答。
- 同时支持内容生成、信息搜集、代码执行和定时自动化。
- 从第一天预留云端 API、本地模型、RAG 和微调扩展能力。
- 先满足个人真实使用，再考虑产品化上线。

## 9. 建设原则

1. 先闭环，再扩展。
   优先让少数核心任务完整可用，例如简历模拟面试、arXiv 日报、网页信息汇总和内容生成。

2. 先 API，后本地模型。
   初期使用成熟模型 API 快速验证产品价值；后续再逐步接入本地模型，降低成本并增强隐私能力。

3. 先模板化，再智能体化。
   初期通过固定任务模板保证稳定性；后续再引入多智能体规划、工具调用和自主执行。

4. 先个人使用，后上线。
   先用个人真实需求检验产品，再根据高频任务和稳定能力选择商业化方向。

5. 人类最终确认。
   面试建议、论文专利、股票预测、代码执行等高风险场景都需要用户最终确认。

## 10. 功能范围

### 10.1 MVP 范围

MVP 阶段建议优先建设以下模块：

1. 用户与基础工作台
   - 本地单用户登录或简单访问控制。
   - 首页任务入口。
   - 历史任务列表。
   - 任务详情页。

2. 模型 API 接入
   - 支持配置 API Key。
   - 支持选择模型。
   - 支持基础对话和任务调用。
   - 支持流式输出。

3. 文件上传与解析
   - 支持上传简历、文档、文本资料。
   - 支持 Markdown、TXT、PDF、DOCX 等常见格式。
   - 保存原文件和解析文本。

4. 简历与模拟面试模块
   - 简历分析。
   - 简历优化建议。
   - 岗位 JD 匹配。
   - 模拟面试问题生成。
   - 面试回答评分与复盘。

5. 内容创作模块
   - 支持论文、专利、小说、剧本、歌词、小红书、知乎、公众号等任务模板。
   - 支持大纲生成、正文生成、润色改写。
   - 支持保存多个版本。

6. 信息搜集与汇总模块
   - 支持输入 URL 或关键词。
   - 支持网页内容抓取。
   - 支持摘要和汇总报告。
   - 支持导出 Markdown。

7. arXiv 论文日报模块
   - 支持配置关键词和方向。
   - 支持每日拉取最新论文。
   - 支持生成中文简报。
   - 支持保存历史日报。

### 10.2 MVP 暂不做或弱化的范围

以下内容建议放到后续版本：

- 完整多用户系统。
- 在线支付和订阅。
- 复杂权限管理。
- 多团队协作。
- 高可靠分布式任务调度。
- 完整本地模型微调平台。
- 专业金融投研系统。
- 专业专利法律审查系统。
- 大规模爬虫平台。

## 11. 技术路线

### 11.1 初期技术方案

建议初期采用“Web 平台 + 后端 API + 大模型 API + 数据库 + 任务调度”的架构。

可选技术栈：

- 前端：Next.js / React。
- 后端：Python FastAPI 或 Node.js。
- 数据库：PostgreSQL，个人阶段也可先用 SQLite。
- 文件存储：本地文件系统，后续可切换对象存储。
- 任务队列：Celery / Redis Queue / BullMQ，个人阶段可先用简单定时任务。
- 模型接入：OpenAI API、其他兼容 OpenAI 格式的模型 API。
- 网页抓取：Playwright、Requests、BeautifulSoup、Firecrawl 等。
- 文档解析：PDF、DOCX、Markdown、TXT 解析工具。
- 向量检索：Chroma、Qdrant、Milvus 或 pgvector。

### 11.2 中期技术方案

中期加入 RAG、工具调用和任务编排。

重点能力：

- 文档向量化。
- 知识库检索。
- 多轮任务状态管理。
- 工具调用框架。
- 定时任务配置。
- 任务失败重试。
- 报告自动生成。
- 多模型路由。

### 11.3 后期技术方案

后期探索本地模型和微调。

重点方向：

- 本地模型部署：Ollama、vLLM、LM Studio、llama.cpp 等。
- 本地小模型：用于摘要、分类、标签、初筛、格式化等低成本任务。
- 云端大模型：用于复杂推理、长文本写作、代码、规划和高质量生成。
- RAG：优先于微调，用于个人知识库、论文资料、项目资料和历史输出。
- 微调：用于稳定风格、固定格式、专门任务和私有语料适配。
- 混合调度：根据任务难度、隐私等级、成本和速度选择模型。

## 12. 数据与知识管理

系统需要沉淀以下数据：

- 用户上传文件。
- 任务输入。
- 模型输出。
- 历史版本。
- 简历和岗位信息。
- 面试题库与面试记录。
- 论文列表和论文摘要。
- 网站抓取结果。
- 股票信息和分析报告。
- Prompt 模板。
- 模型配置。
- 任务执行日志。

数据设计需要支持后续检索、复用、导出和删除。

## 13. 关键流程

### 13.1 简历模拟面试流程

1. 上传简历。
2. 输入目标岗位或岗位 JD。
3. 系统解析简历。
4. 系统分析岗位匹配度。
5. 系统生成简历修改建议。
6. 系统生成模拟面试问题。
7. 用户逐题回答。
8. 系统评价回答质量。
9. 系统生成面试复盘报告。

### 13.2 内容创作流程

1. 选择创作类型。
2. 输入主题、要求、风格和素材。
3. 系统生成大纲。
4. 用户确认或修改大纲。
5. 系统生成正文。
6. 用户继续润色、改写或扩写。
7. 保存版本并导出。

### 13.3 信息搜集流程

1. 输入网站、关键词或信息源。
2. 系统抓取网页内容。
3. 系统清洗和去重。
4. 系统按主题汇总。
5. 系统生成报告。
6. 用户保存、导出或设置为定时任务。

### 13.4 arXiv 日报流程

1. 配置研究方向和关键词。
2. 系统每日自动拉取论文。
3. 系统筛选相关论文。
4. 系统生成中文摘要和推荐理由。
5. 系统生成日报。
6. 用户查看、收藏或标记精读。

## 15. 成功标准

### 15.1 个人使用成功标准

- 能稳定完成简历分析和模拟面试。
- 能生成可继续修改的论文、专利、小说、剧本、歌词和社媒内容草稿。
- 能对指定网站进行信息搜集并生成可读报告。
- 能每日自动汇总 arXiv 指定方向论文。
- 能辅助搜集股票信息并生成分析报告。
- 所有任务有历史记录，方便复用和追踪。
- 使用效率明显高于手动切换多个工具。

### 15.2 产品化成功标准

- 核心流程对非开发者也可使用。
- 输出质量稳定，失败率可控。
- 任务结果可保存、导出和复用。
- 模型成本可监控。
- 敏感数据有基本保护机制。
- 可以部署到服务器并持续运行。
- 至少形成一个明确的垂直场景卖点，例如“AI 求职面试助手”“AI 论文追踪助手”或“AI 内容创作工作台”。

## 16. 风险与应对

### 16.1 范围过大风险

风险：项目覆盖面很广，容易同时做很多模块，导致长期没有可用版本。

应对：

- MVP 只做最核心的 3 到 4 个闭环。
- 每个模块先做模板化流程，再做复杂智能体。
- 每周用真实任务验证一次。

### 16.2 输出质量不稳定风险

风险：大模型生成内容可能不准确、虚构或风格不稳定。

应对：

- 为不同任务设计固定 Prompt 模板。
- 对高风险内容增加事实检查和人工确认。
- 保留引用来源和原始资料。
- 对输出进行结构化约束。

### 16.3 信息抓取失败风险

风险：不同网站结构变化、反爬限制、登录限制会导致抓取失败。

应对：

- 优先使用 RSS、公开 API 和稳定信息源。
- 对网页抓取增加失败记录和重试机制。
- 对重要信息源单独适配。

### 16.4 成本风险

风险：频繁调用云端 API 可能带来较高成本。

应对：

- 增加调用日志和成本统计。
- 对长文档先摘要再处理。
- 对简单任务使用低成本模型。
- 后期引入本地小模型分担任务。

### 16.5 合规与责任风险

风险：论文、专利、股票预测和网页抓取涉及真实性、版权、法律和投资风险。

应对：

- 明确系统定位为辅助工具。
- 保留用户最终确认机制。
- 股票模块增加非投资建议声明。
- 专利模块提示需专业审查。
- 网页抓取遵守目标网站规则。

### 16.6 本地模型效果不足风险

风险：本地小模型在复杂写作和推理任务上可能效果不足。

应对：

- 不把本地模型作为初期依赖。
- 本地模型优先承担摘要、分类、去重、格式化等任务。
- 复杂任务继续使用云端强模型。
- 通过 RAG 提升本地模型在特定资料上的效果。

## 17. 边界说明

项目初期不追求一次性完成所有 AI 能力，而是优先完成可验证、可复用、可自动化的核心工作流。

系统不是法律顾问、投资顾问、医学顾问或学术诚信替代工具。它提供结构化辅助、资料整理、草稿生成、分析参考和效率提升，最终判断和责任由用户承担。
