## 1. 文档信息

### 1.1 文档名称

晨枢 AI - 产品类 - PRD 产品需求文档

### 1.2 产品名称

晨枢 AI

### 1.3 产品阶段

个人自用 MVP 阶段，后续预留上线、SaaS 化、本地部署模型、RAG 和微调扩展能力。

### 1.4 文档目的

本文档用于描述晨枢 AI 的产品需求，明确用户角色、业务场景、功能模块、核心流程、页面需求、数据需求、权限需求、非功能需求和验收标准，为后续原型设计、技术架构设计和开发实现提供依据。

## 2. 产品概述

晨枢 AI 是一个面向个人知识工作者的 AI 任务中枢，帮助用户通过统一平台完成简历优化、模拟面试、论文与专利辅助、小说剧本歌词创作、新媒体内容生产、代码实验、网页信息搜集、arXiv 论文追踪和股票研究辅助等任务。

产品初期以个人使用为核心，重点不是做“大而全”的复杂平台，而是先完成几个高频任务闭环：

- 上传资料。
- 创建任务。
- 调用模型。
- 生成结构化结果。
- 保存历史记录。
- 支持再次编辑、导出和复用。
- 对周期性任务提供自动汇总能力。

## 3. 产品目标

### 3.1 MVP 目标

1. 搭建一个可运行的本地或私有 Web 平台。
2. 支持用户配置大模型 API，并完成基础模型调用。
3. 支持文件上传、解析和作为任务上下文使用。
4. 支持简历分析、模拟面试和面试复盘。
5. 支持多类型内容创作任务。
6. 支持网页信息搜集、摘要和汇总报告。
7. 支持 arXiv 指定方向论文日报。
8. 支持任务历史保存和 Markdown 导出。

### 3.2 中期目标

1. 增加定时任务、任务失败重试和自动报告归档。
2. 增加轻量知识库与 RAG 检索。
3. 增加多模型配置和模型路由。
4. 增加股票信息搜集与研究辅助。
5. 增加 Prompt 模板库和输出版本管理。

### 3.3 长期目标

1. 接入本地模型和本地小模型。
2. 探索本地小模型 + 云端 API 的混合方案。
3. 探索基于个人数据和固定任务格式的微调方案。
4. 支持多用户、权限、部署和上线。
5. 形成可对外发布的产品版本。

## 4. 用户角色

### 4.1 个人用户

当前 MVP 的唯一核心角色。

权限：

- 配置模型 API。
- 上传和管理文件。
- 创建和查看任务。
- 使用全部任务模板。
- 查看历史记录。
- 导出结果。
- 配置 arXiv 方向。
- 配置自动化任务。

### 4.2 管理员

MVP 阶段可以与个人用户合并，后期上线时独立。

权限：

- 管理用户。
- 管理模型配置。
- 查看系统日志。
- 查看成本统计。
- 管理任务模板。
- 管理系统设置。

### 4.3 访客用户

MVP 阶段不支持。后期上线时可作为试用用户。

权限：

- 体验部分公开模板。
- 无法查看他人数据。
- 无法使用高成本任务或定时任务。

## 5. 需求优先级定义

### 5.1 P0

MVP 必须完成。没有这些功能，产品无法形成基本闭环。

### 5.2 P1

MVP 后优先增强。可以提升体验、稳定性和自动化能力，但不阻塞第一版使用。

### 5.3 P2

中后期能力。主要面向产品化、本地模型、团队协作和商业化。

## 7. 核心业务流程

### 7.1 通用 AI 任务流程

1. 用户进入工作台。
2. 用户选择任务类型。
3. 用户填写任务表单。
4. 用户上传或选择上下文文件。
5. 用户选择模型和输出格式。
6. 用户点击开始生成。
7. 系统创建任务记录。
8. 系统调用模型或工具。
9. 系统流式展示结果。
10. 用户保存、编辑、重新生成或导出结果。

### 7.2 简历模拟面试流程

1. 用户上传简历。
2. 用户输入目标岗位或岗位 JD。
3. 系统解析简历文本。
4. 系统生成简历结构分析。
5. 系统给出简历修改建议。
6. 系统生成岗位匹配度分析。
7. 系统生成模拟面试题。
8. 用户逐题回答。
9. 系统评价回答质量并生成追问。
10. 系统生成面试复盘报告。

### 7.3 内容创作流程

1. 用户选择创作类型。
2. 用户输入主题、目标、风格、篇幅和素材。
3. 系统生成大纲。
4. 用户确认或修改大纲。
5. 系统生成正文。
6. 用户执行润色、扩写、缩写、改风格或分平台改写。
7. 系统保存版本。
8. 用户导出结果。

### 7.4 信息搜集流程

1. 用户输入 URL、关键词或网站列表。
2. 用户选择搜集范围和输出要求。
3. 系统抓取网页或搜索结果。
4. 系统提取正文、标题、时间、来源和链接。
5. 系统去重和分类。
6. 系统生成摘要和汇总报告。
7. 用户查看来源、保存报告或设置为定时任务。

### 7.5 arXiv 日报流程

1. 用户配置研究方向、关键词、分类和排除词。
2. 系统按计划拉取 arXiv 最新论文。
3. 系统根据关键词和相关性筛选论文。
4. 系统生成论文中文摘要。
5. 系统提取贡献、方法、实验和结论。
6. 系统标记推荐精读论文。
7. 系统生成每日简报并保存。

## 8. 页面需求

### 8.1 工作台首页

目标：提供任务入口和近期任务概览。

页面内容：

- 产品名称和当前运行状态。
- 快捷任务入口。
- 最近任务列表。
- 今日自动报告入口。
- 模型连接状态。
- API 成本或调用次数概览。

主要操作：

- 新建任务。
- 打开历史任务。
- 查看自动报告。
- 进入模型设置。

验收标准：

- 用户可以在 3 秒内找到新建任务入口。
- 用户可以从首页进入任一 P0 模块。
- 最近任务可按时间倒序展示。

### 8.2 任务创建页

目标：让用户选择任务类型并填写必要输入。

页面内容：

- 任务类型选择。
- 任务名称。
- 任务说明。
- 输入文本框。
- 文件选择或上传。
- 模型选择。
- 输出格式选择。
- 高级参数折叠区。

主要操作：

- 创建任务。
- 保存草稿。
- 开始执行。

验收标准：

- 必填项为空时给出明确提示。
- 用户可以选择已上传文件作为上下文。
- 用户点击执行后进入任务详情页并看到执行状态。

### 8.3 任务详情页

目标：展示任务输入、执行过程和输出结果。

页面内容：

- 任务名称。
- 任务类型。
- 执行状态。
- 输入内容。
- 关联文件。
- 模型信息。
- 流式输出区域。
- 历史版本。
- 操作按钮。

主要操作：

- 重新生成。
- 基于结果继续追问。
- 编辑结果。
- 保存版本。
- 导出 Markdown。
- 删除任务。

验收标准：

- 任务状态清晰可见。
- 生成失败时显示失败原因。
- 输出结果可以复制和导出。

### 8.4 文件管理页

目标：管理上传文件和解析文本。

页面内容：

- 文件列表。
- 文件名称。
- 文件类型。
- 文件大小。
- 上传时间。
- 解析状态。
- 解析文本预览。

主要操作：

- 上传文件。
- 查看文件。
- 重新解析。
- 删除文件。
- 用文件创建任务。

验收标准：

- 支持 Markdown、TXT、PDF、DOCX。
- 文件上传后显示解析状态。
- 解析失败时有错误提示。

### 8.5 简历与模拟面试页

目标：完成从简历分析到模拟面试复盘的完整流程。

页面内容：

- 简历上传区。
- 岗位 JD 输入区。
- 简历分析结果。
- 修改建议。
- 面试题列表。
- 面试回答输入区。
- 回答评价。
- 复盘报告。

主要操作：

- 分析简历。
- 生成面试题。
- 开始面试。
- 提交回答。
- 生成复盘。
- 导出报告。

验收标准：

- 系统能识别简历中的教育、项目、技能和经历。
- 系统能根据岗位 JD 生成针对性问题。
- 复盘报告包含优势、不足、改进建议和下一步准备计划。

### 8.6 内容创作页

目标：提供多类型内容生成模板。

页面内容：

- 创作类型选择。
- 主题输入。
- 风格选择。
- 篇幅选择。
- 目标平台选择。
- 素材输入。
- 大纲区域。
- 正文区域。
- 改写操作区。

主要操作：

- 生成大纲。
- 生成正文。
- 润色。
- 扩写。
- 缩写。
- 改风格。
- 分平台改写。

- 用户可以选择至少 8 种内容类型。
- 输出内容符合所选类型的基本结构。
- 用户可以基于已有输出继续修改。

### 8.7 信息搜集页

目标：支持用户从网页和关键词中搜集信息并生成报告。

页面内容：

- 关键词输入。

- 抓取状态。
- 来源结果。
- 摘要结果。
- 汇总报告。

主要操作：

- 添加 URL。
- 添加关键词。
- 开始搜集。
- 查看来源。
- 生成报告。
- 保存为定时任务。

验收标准：

- 系统能展示每条信息的来源链接。
- 系统能对多来源内容进行去重和汇总。
- 报告中应区分事实、摘要和模型分析。

### 8.8 arXiv 日报页

目标：支持研究方向配置和每日论文简报查看。

页面内容：

- 方向配置。
- 关键词配置。
- arXiv 分类配置。
- 今日论文列表。
- 论文摘要。
- 精读推荐。
- 历史日报。

主要操作：

- 新增方向。
- 编辑关键词。
- 手动拉取。
- 生成日报。
- 收藏论文。
- 导出日报。

验收标准：

### 8.9 模型设置页

目标：管理模型 API 和默认调用策略。

页面内容：

- API Key。
- Base URL。

- 默认模型。

- 测试失败时显示明确错误。
- 至少支持 OpenAI 兼容接口。

## 9. 功能需求详情

### 9.1 基础工作台

需求编号：REQ-DASHBOARD-001

需求描述：

系统需要提供统一工作台，集中展示任务入口、最近任务、自动报告和模型状态。

用户故事：

作为个人用户，我希望打开系统后能快速进入常用 AI 任务，而不是在多个工具之间寻找入口。

功能点：

- 展示 P0 任务入口。
- 展示最近任务。
- 展示自动报告入口。
- 展示模型连接状态。
- 支持快捷创建任务。

优先级：P0

验收标准：

- 首页可以进入简历面试、内容创作、信息搜集、arXiv 日报。
- 最近任务按更新时间倒序排列。
- 模型未配置时提示用户前往设置。

### 9.2 模型 API 配置

需求编号：REQ-MODEL-001

需求描述：

系统需要支持用户配置模型 API，使后续任务可以通过云端模型完成生成、摘要和分析。

用户故事：

作为个人用户，我希望能填写自己的 API Key，并选择不同模型来执行不同任务。

功能点：

- 支持 OpenAI 兼容 API。
- 支持 API Key、Base URL、模型名称配置。
- 支持默认模型设置。
- 支持连接测试。
- 支持配置启用和禁用。

优先级：P0

验收标准：

- 未配置模型时，执行任务前应阻止并提示。
- 配置完成后可以发起测试调用。
- API Key 不以明文长期展示在页面上。

### 9.3 文件上传与解析

需求编号：REQ-FILE-001

需求描述：

系统需要支持上传常见文档，并将文档解析为文本，供任务使用。

用户故事：

作为用户，我希望上传简历、论文资料或写作素材后，系统能自动读取其中内容并作为 AI 上下文。

功能点：

- 支持 Markdown。
- 支持 TXT。
- 支持 PDF。
- 支持 DOCX。
- 展示文件解析状态。
- 支持解析文本预览。
- 支持删除文件。

优先级：P0

验收标准：

- 上传成功后文件出现在文件列表。
- 解析成功后可以在任务中选择该文件。
- 解析失败时显示失败原因。

### 9.4 通用任务系统

需求编号：REQ-TASK-001

需求描述：

系统需要提供统一任务模型，用于保存不同类型任务的输入、上下文、执行状态和输出。

用户故事：

作为用户，我希望每次生成结果都有记录，后续可以查看、复用、修改和导出。

功能点：

- 创建任务。
- 保存任务输入。
- 保存任务状态。
- 保存模型输出。
- 支持任务重新执行。
- 支持任务删除。
- 支持任务搜索和筛选。

优先级：P0

验收标准：

- 每个任务都有唯一 ID。
- 每个任务至少包含类型、名称、输入、状态、输出、创建时间和更新时间。
- 生成失败的任务也应保留错误记录。

### 9.5 简历与模拟面试

需求编号：REQ-INTERVIEW-001

需求描述：

系统需要支持用户上传简历并输入目标岗位，自动完成简历分析、修改建议、面试问题生成和复盘。

用户故事：

作为求职者，我希望系统基于我的简历和目标岗位模拟真实面试，并指出我的简历和回答可以如何优化。

功能点：

- 简历结构解析。
- 岗位 JD 分析。
- 岗位匹配度分析。
- 简历修改建议。
- 面试题生成。
- 分轮回答。
- 回答评价。
- 追问建议。
- 面试复盘报告。

优先级：P0

验收标准：

- 简历分析结果包含优势、问题和修改建议。
- 面试题应与目标岗位相关。
- 回答评价包含表达、逻辑、专业性和改进建议。

### 9.6 内容创作

需求编号：REQ-CONTENT-001

需求描述：

系统需要支持多种内容创作模板，帮助用户生成大纲、正文、改写和润色版本。

用户故事：

作为内容创作者，我希望选择不同内容类型后，系统能按该类型的结构生成可修改的草稿。

功能点：

- 论文草稿。
- 专利草稿。
- 小说。
- 剧本。
- 歌词。
- 小红书。
- 知乎。
- 公众号。
- 大纲生成。
- 正文生成。
- 改写润色。
- 多版本保存。

优先级：P0

验收标准：

- 每种内容类型有独立输入字段或模板。
- 输出内容符合所选平台或文体的结构。
- 用户可以对生成结果继续执行润色、扩写、缩写和改风格。

### 9.7 信息搜集与汇总

需求编号：REQ-RESEARCH-001

需求描述：

系统需要支持从 URL 或关键词搜集信息，生成摘要、分类和汇总报告。

用户故事：

作为研究者，我希望输入几个网站或关键词后，系统能帮我整理重要信息并生成可读报告。

功能点：

- URL 输入。
- 关键词输入。
- 网页抓取。
- 正文提取。
- 来源保留。
- 内容去重。
- 摘要生成。
- 汇总报告。

优先级：P0

验收标准：

- 报告中包含来源链接。
- 报告中区分原始事实和模型总结。
- 抓取失败时不影响其他来源继续处理。

### 9.8 arXiv 论文日报

需求编号：REQ-ARXIV-001

需求描述：

系统需要支持配置研究方向并定期拉取 arXiv 最新论文，生成中文论文日报。

用户故事：

作为研究者，我希望每天自动收到自己关注方向的新论文摘要，快速判断哪些值得精读。

功能点：

- 方向配置。
- 关键词配置。
- arXiv 分类配置。
- 手动拉取。
- 定时拉取。
- 论文相关性筛选。
- 中文摘要生成。
- 精读推荐。
- 历史日报保存。

优先级：P0

验收标准：

- 用户可以配置至少一个研究方向。
- 每篇论文包含标题、作者、链接、发布时间和摘要。
- 日报可以手动生成并保存。

### 9.9 股票研究辅助

## 11. 状态定义

### 11.1 任务状态

- 草稿：用户已填写但未执行。
- 排队中：任务已提交，等待执行。
- 执行中：系统正在调用模型或工具。
- 已完成：任务成功完成。
- 已失败：任务执行失败。
- 已取消：用户主动取消任务。

### 11.2 文件解析状态

- 未解析。
- 解析中。
- 解析成功。
- 解析失败。

### 11.3 自动任务状态

- 未启用。
- 已启用。
- 执行中。
- 最近成功。
- 最近失败。
- 已暂停。

## 12. 权限需求

MVP 阶段可以采用单用户模式，但仍建议预留权限边界。

### 12.1 单用户模式

- 本地运行时可以不强制登录。
- 私有服务器运行时建议启用简单密码登录。
- 用户拥有全部数据和功能权限。

### 12.2 后期多用户模式

- 用户只能访问自己的文件、任务和模型配置。
- 管理员可以管理系统设置。
- API Key 不能被其他用户查看。
- 自动任务只能访问创建者授权的数据。

## 13. 非功能需求

### 13.1 性能需求

- 首页加载时间应尽量控制在 3 秒以内。
- 普通文本任务提交后应在 2 秒内显示执行状态。
- 流式输出应尽快展示首字。
- 文件解析任务需要有状态反馈。

### 13.2 稳定性需求

- 模型调用失败时不能导致系统崩溃。
- 单个信息源抓取失败不能中断全部汇总任务。
- 任务失败应保留错误信息，方便重试和排查。

### 13.3 安全需求

- API Key 不应明文展示。
- 上传文件应限制大小和类型。
- 删除任务和文件前应确认。
- 后期上线需要增加身份认证、访问控制和日志审计。

### 13.4 隐私需求

- 简历、研究资料和个人文档属于敏感数据。
- 系统需要明确哪些内容会发送给模型 API。
- 后续本地模型方案应优先用于高隐私场景。

### 13.5 可扩展性需求

- 模型调用应封装为统一接口。
- 任务类型应可扩展。
- 文件解析器应可扩展。
- 信息源抓取器应可扩展。
- 后续可接入本地模型和 RAG。

## 14. Prompt 与输出要求

### 14.1 Prompt 管理

系统需要为不同任务类型配置不同 Prompt 模板。

模板应包含：

- 角色设定。
- 输入变量。
- 输出结构。
- 质量要求。
- 风险提示。
- 语言风格。

### 14.2 输出格式

默认输出格式为 Markdown。

不同任务应有不同结构：

- 简历分析：优势、问题、修改建议、示例改写。
- 面试复盘：问题、用户回答、评价、改进建议。
- 论文日报：论文列表、摘要、贡献、方法、推荐理由。
- 信息汇总：来源、事实摘要、分类总结、趋势判断。
- 股票报告：行情概览、新闻摘要、风险提示、研究结论。

### 14.3 输出质量约束

- 不允许伪造来源链接。
- 不允许把不确定内容写成确定事实。
- 股票模块必须提示风险。
- 论文和专利模块必须提示用户复核真实性和合规性。
- 代码模块应提示运行环境和依赖。

### 15.1 MVP 运行环境

- 支持浏览器访问。
- 支持本地文件存储。
- 支持环境变量或配置页保存 API Key。

### 15.2 后期部署环境

- 支持服务器部署。
- 支持数据库迁移。
- 支持对象存储。
- 支持 HTTPS。
- 支持后台任务运行。
- 支持日志和监控。

## 16. 风险与限制

### 16.1 大模型幻觉

模型可能生成错误内容。系统需要通过来源引用、结构化输出和用户复核降低风险。

### 16.2 网页抓取限制

部分网站可能有反爬、登录或版权限制。系统应优先使用公开 API、RSS 和允许访问的信息源。

### 16.3 投资风险

股票分析仅用于研究辅助，不提供投资建议，不支持交易执行。

### 16.4 学术合规风险

论文和专利模块只提供辅助写作，不应支持伪造实验、抄袭或规避学术规范。 

### 16.5 成本风险

频繁调用云端 API 可能产生成本。后续需要增加调用日志、成本统计和模型分流。

## 17. MVP 验收标准

MVP 达到以下标准即可认为第一版产品需求完成：

1. 用户可以配置模型 API，并成功完成测试调用。
2. 用户可以上传文档，并在任务中引用文档内容。
3. 用户可以创建任务，并查看任务执行状态。
4. 用户可以完成一次简历分析和模拟面试复盘。
5. 用户可以生成至少一种论文或专利草稿。
6. 用户可以生成小说、剧本、歌词或新媒体内容草稿。
7. 用户可以输入 URL 并生成信息汇总报告。
8. 用户可以配置 arXiv 方向并生成论文日报。
9. 用户可以查看历史任务。
10. 用户可以导出 Markdown 结果。
