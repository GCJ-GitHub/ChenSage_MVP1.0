## 1. 文档目的

本文档用于明确晨枢 AI 的产品定位、目标用户、核心价值、使用场景、功能范围、阶段边界和暂不建设内容。

项目当前阶段以个人使用为主，目标是先做出一个真实可用的 AI 工作台；后期在个人使用验证稳定后，再逐步探索上线、商业化、本地部署模型、RAG 和微调方案。

## 2. 产品一句话定位

晨枢 AI 是一个面向个人知识工作者的 AI 任务中枢，帮助用户在一个平台内完成写作创作、简历面试、科研论文追踪、信息搜集、代码实验和投资研究等复杂任务。

## 3. 产品核心定位

晨枢 AI 不是一个普通聊天机器人，也不是单一写作工具、单一爬虫工具或单一知识库工具。

它的核心定位是：

1. 个人 AI 工作台。
   用户可以在统一入口中创建、管理和复用不同类型的 AI 任务。

2. 多场景内容与研究生产平台。
   系统围绕简历面试、论文专利、小说剧本、歌词、新媒体推文、代码实验、网页信息汇总、arXiv 论文日报、股票分析等场景提供结构化能力。

3. 长期任务与自动化中枢。
   系统不只处理一次性问答，还要支持长期任务、定时任务、历史记录、报告沉淀和知识复用。

4. 云端 API 与本地模型的混合入口。
   初期以云端模型 API 快速落地，后期逐步接入本地模型、本地小模型、RAG 和微调方案。

## 4. 产品愿景

晨枢 AI 的长期愿景是成为个人知识工作的中枢系统。

用户不需要在多个 AI 工具、搜索网站、文档工具、代码工具和资讯网站之间反复切换，而是可以通过晨枢 AI 发起任务、调用模型、读取文件、搜集信息、生成报告、保存结果，并逐步形成属于自己的知识与任务资产。

## 5. 目标用户

### 5.1 当前核心用户

当前阶段的核心用户是项目创建者本人。

用户特征：

- 需要频繁写作、研究、学习、开发和分析。
- 需要处理多种 AI 任务，而不是单一聊天。
- 接受早期版本以实用为主，界面可以逐步打磨。
- 关注效率、自动化、可复用和结果质量。
- 希望后期探索本地部署模型和微调方案。

### 5.2 后期潜在用户

后期上线后，可以面向以下用户群体：

1. 求职者。
   需要简历优化、岗位匹配、模拟面试、面试复盘和能力补强建议。

2. 学生与研究者。
   需要论文追踪、论文阅读、文献综述、论文写作、实验代码和研究汇报。

3. 内容创作者。
   需要小说、剧本、歌词、小红书、知乎、公众号等内容生产与改写。

4. 独立开发者。
   需要代码生成、实验运行、Bug 分析、技术方案整理和自动文档。

5. 投资研究者。
   需要股票信息搜集、新闻摘要、财务信息整理、趋势分析和风险提示。

6. 小团队用户。
   需要内部知识库、自动报告、资料汇总和多任务 AI 助手。

## 6. 用户核心问题

晨枢 AI 主要解决以下问题：

1. 工具分散。
   不同任务需要在不同网站和软件之间切换，信息和结果难以沉淀。

2. AI 对话不可复用。
   单次聊天可以得到结果，但任务流程、文件上下文、Prompt、历史版本和输出格式难以稳定复用。

3. 重复信息搜集耗时。
   arXiv 论文、行业资讯、网站信息、股票信息等内容需要长期追踪，手动搜集效率低。

4. 内容生产链路长。
   从选题、资料搜集、大纲、初稿、改写、润色、导出到复盘，经常需要多轮操作。

5. 本地模型探索缺少入口。
   用户希望未来尝试本地模型、小模型、RAG 或微调，但需要一个统一平台承载这些能力。

## 7. 产品核心价值

### 7.1 效率价值

通过任务模板、自动化信息搜集和模型调用，减少重复劳动，提高写作、研究、开发和分析效率。

### 7.2 质量价值

通过结构化流程、参考资料输入、版本管理和结果复盘，提高输出内容的完整性、针对性和可修改性。

### 7.3 沉淀价值

将简历、岗位、论文、写作素材、网页资料、股票分析、代码实验和历史输出沉淀为可检索、可复用的个人知识资产。

### 7.4 自动化价值

将每日论文追踪、网站信息汇总、股票信息简报等重复任务变成自动运行的长期任务。

### 7.5 扩展价值

通过统一模型接口和工具接口，为后续本地模型、微调、RAG、插件化工具和产品上线预留空间。

## 8. 核心使用场景

### 8.1 简历优化与模拟面试

用户上传简历，输入目标岗位或岗位 JD，系统自动分析简历、提取亮点、指出问题、给出修改建议，并基于岗位要求生成模拟面试问题。

系统支持多轮面试问答，用户回答后，系统给出评分、追问建议、表达优化建议和面试复盘报告。

### 8.2 论文与专利辅助

用户输入研究方向、已有资料、实验结果或技术方案，系统帮助生成论文大纲、文献综述草稿、章节草稿、摘要、引言、结论、专利交底书和权利要求书初稿。

该场景定位为辅助写作，不替代学术真实性检查、实验真实性验证和专利法律审查。

### 8.3 创意写作

用户可以用系统写小说、剧本和歌词。

系统支持世界观设定、人物设定、章节大纲、分场设计、正文续写、对话润色、歌词主题设计、押韵辅助和多版本改写。

### 8.4 新媒体内容生产

用户可以围绕一个主题生成小红书、知乎和公众号内容。

系统支持选题、标题、大纲、正文、平台风格改写、标签建议和一稿多发改写。

### 8.5 代码与实验

用户输入实验目标、代码需求或报错信息，系统辅助生成代码、解释代码、分析错误、生成实验脚本、整理实验结果和生成技术报告。

后续可接入本地代码运行环境、Notebook、容器或远程服务器。

### 8.6 网站信息搜集与汇总

用户输入目标网站、关键词、抓取频率和输出要求，系统自动搜集信息、去重、摘要、分类、对比，并生成 Markdown 报告。

### 8.7 arXiv 每日论文汇总

用户配置研究方向、关键词、分类或作者，系统每天自动拉取 arXiv 最新论文，按相关性筛选，生成中文摘要、贡献点、方法概述、实验结论和精读推荐。

### 8.8 股票信息搜集与分析

用户配置股票池、行业或关键词，系统搜集行情、新闻、公告和财务信息，生成基础分析、风险提示和趋势判断。

该场景仅作为研究辅助，不提供确定性投资建议。

## 9. 产品形态

### 9.1 当前阶段产品形态

当前阶段建议建设为本地或私有 Web 应用。

主要特点：

- 单用户或弱登录。
- 本地文件存储。
- API Key 由用户自行配置。
- 支持浏览器访问。
- 支持本地运行和后续服务器部署。

### 9.2 后期产品形态

后期可演进为：

- 多用户 Web SaaS。
- 私有化部署工具。
- 面向特定场景的垂直产品。
- 本地模型 + 云端 API 混合平台。
- 个人知识库与自动化任务平台。

## 11. MVP 范围

MVP 阶段的目标是做出个人可用的最小闭环，而不是一次性完成所有功能。

### 11.1 MVP 必须包含

1. 基础工作台。
   - 首页任务入口。
   - 任务列表。
   - 任务详情。
   - 历史输出保存。

2. 模型 API 接入。
   - API Key 配置。
   - 模型选择。
   - 流式输出。
   - 调用失败提示。

3. 文件上传与解析。
   - 支持 Markdown、TXT、PDF、DOCX。
   - 支持简历、资料和写作素材上传。

4. 简历与模拟面试。
   - 简历分析。
   - 岗位 JD 匹配。
   - 简历修改建议。
   - 面试问题生成。
   - 面试复盘。

5. 内容创作。
   - 论文草稿。
   - 专利草稿。
   - 小说。
   - 剧本。
   - 歌词。
   - 小红书。
   - 知乎。
   - 公众号。

6. 信息搜集与汇总。
   - URL 内容抓取。
   - 关键词信息搜集。
   - 摘要和汇总报告。

7. arXiv 论文日报。
   - 方向和关键词配置。
   - 最新论文拉取。
   - 中文摘要。
   - 每日简报保存。

### 11.2 MVP 可延后但需要预留

- 股票分析模块可以先做信息搜集与摘要，预测和策略部分后置。
- 本地模型接入可以先预留接口，暂不作为初版核心依赖。
- 知识库和向量检索可以先做轻量版本，后续增强。
- 定时任务可以先用简单计划任务实现，后续再做完整任务调度系统。

## 12. 非 MVP 范围

以下内容不建议放入第一版：

- 完整商业化支付系统。
- 完整多租户团队协作。
- 精细权限体系。
- 大规模爬虫平台。
- 高并发分布式任务系统。
- 专业金融量化交易系统。
- 自动下单或交易执行。
- 专业法律级专利审查。
- 自动发表论文或绕过学术规范的能力。
- 完整模型训练平台。
- 大规模数据标注系统。

## 13. 产品边界

### 13.1 晨枢 AI 要做什么

- 做个人 AI 任务入口。
- 做高频场景的结构化模板。
- 做文件、任务和结果的沉淀。
- 做信息自动搜集和报告生成。
- 做云端 API 与本地模型的统一调度基础。
- 做后续上线和产品化的基础架构。

### 13.2 晨枢 AI 不做什么

- 不承诺生成内容完全正确。
- 不替代专业法律、金融、医学或学术审查。
- 不做黑盒自动投资决策。
- 不做违反网站规则的大规模抓取。
- 不做绕过版权、学术规范或平台规则的功能。
- 不在 MVP 阶段追求复杂商业系统。

## 14. 与普通 AI 聊天工具的区别

普通 AI 聊天工具通常以对话为中心，用户需要反复输入背景、复制资料、保存结果和整理输出。

晨枢 AI 以任务为中心：

- 每个任务有类型。
- 每个任务有输入文件。
- 每个任务有固定流程。
- 每个任务有历史记录。
- 每个任务有输出格式。
- 每个任务可以复用和自动运行。
- 每个任务可以逐步接入工具和模型路由。

## 15. 与知识库工具的区别

普通知识库工具主要解决资料存储和检索问题。

晨枢 AI 不只存资料，还要推动任务完成：

- 根据资料生成内容。
- 根据资料提出问题。
- 根据资料生成报告。
- 根据资料追踪变化。
- 根据资料支持面试、写作、研究和分析。

## 16. 与自动化工具的区别

普通自动化工具擅长执行固定流程，但通常缺少自然语言理解、长文本生成和复杂推理。

晨枢 AI 的自动化重点是 AI 原生任务：

- 自动搜集信息。
- 自动理解内容。
- 自动摘要分类。
- 自动生成报告。
- 自动根据历史上下文改进输出。

## 17. 阶段范围规划

### 17.1 第一阶段：个人可用

目标：完成一个能真实使用的本地 Web 应用。

范围：

- 模型 API 调用。
- 文件上传与解析。
- 简历面试。
- 内容创作。
- 网页信息汇总。
- arXiv 日报。
- 历史任务保存。

### 17.2 第二阶段：自动化增强

目标：让平台能处理长期任务。

范围：

- 定时任务。
- 任务失败重试。
- 报告自动归档。
- 多来源信息汇总。
- 股票信息日报。
- 论文历史库。

### 17.3 第三阶段：知识库与模型路由

目标：让系统具备个人知识沉淀和多模型调度能力。

范围：

- 文档向量化。
- RAG 检索。
- Prompt 模板库。
- 多模型选择。
- 本地小模型接入。
- 成本统计。

### 17.4 第四阶段：产品化上线

目标：将个人工具打磨为可给他人使用的产品。

范围：

- 用户系统。
- 权限管理。
- 部署运维。
- 安全策略。
- 使用统计。
- 反馈系统。
- 付费或授权方案。

## 18. 优先级说明

### 18.1 P0 优先级

P0 是 MVP 必须完成的能力：

- 基础工作台。
- 模型 API 接入。
- 任务历史保存。
- 文件上传与解析。
- 简历分析与模拟面试。
- 内容创作模板。
- URL 信息汇总。
- arXiv 论文日报。

### 18.2 P1 优先级

P1 是 MVP 后应尽快补齐的能力：

- 定时任务。
- 多模型配置。
- Prompt 模板管理。
- Markdown 导出。
- 股票信息汇总。
- 任务失败重试。
- 轻量知识库。

### 18.3 P2 优先级

P2 是中后期增强能力：

- 本地模型接入。
- RAG 知识库。
- 模型成本统计。
- 多用户系统。
- 团队协作。
- 微调实验。
- 商业化上线。

## 19. 核心指标

### 19.1 个人使用指标

- 每周实际使用次数。
- 单个任务节省时间。
- 输出结果可继续使用比例。
- 每日报告稳定生成次数。
- 用户手动返工次数。
- 模型调用失败次数。

### 19.2 产品化指标

- 新用户完成首个任务比例。
- 用户 7 日留存。
- 平均每用户任务数。
- 单任务平均模型成本。
- 报告导出次数。
- 用户反馈满意度。

## 20. 风险边界

### 20.1 内容真实性

系统生成的论文、专利、股票分析、网页汇总和代码解释可能存在错误，需要保留来源、提示用户复核，并在重要场景中增加校验环节。

### 20.2 投资风险

股票分析模块只提供研究辅助和信息整理，不提供确定性投资建议，不执行交易，不承诺收益。

### 20.3 学术与版权风险

论文和内容创作模块需要遵守学术规范和版权规范，不应支持抄袭、伪造数据或规避平台规则。

### 20.4 隐私风险

简历、面试、研究资料和个人文档可能包含敏感信息。平台需要在后续设计中考虑本地存储、访问控制、脱敏、删除和模型调用提示。

## 21. 结论

晨枢 AI 当前最合理的定位是：先做个人可用的 AI 任务中枢，再逐步演进为可上线的多场景 AI 工作平台。

第一阶段不追求功能大而全，而是优先完成简历面试、内容创作、信息汇总和 arXiv 日报这几个高频闭环。等这些场景稳定后，再补充股票分析、知识库、本地模型、RAG、微调和商业化能力。
