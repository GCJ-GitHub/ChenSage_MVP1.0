# ChenSage_MVP1.0

晨枢 AI（ChenSage_MVP1.0）是一个个人 AI 任务中枢的 MVP 版本，用于把内容创作、模拟面试、信息搜集、arXiv 论文日报、模型配置、提示词模板、文件解析、历史任务与统一导出整合到一个本地工作台中。

> 当前状态：MVP 初步完成，适合本地个人使用、功能验证和后续云原生化改造。暂不建议直接作为公开生产服务部署。

## 项目用途

ChenSage_MVP1.0 的目标是提供一个可扩展的 AI 工作台：

- 给简历和岗位描述，生成简历分析、模拟面试题、回答评价和复盘报告。
- 支持论文、专利、小说、剧本、歌词、小红书、知乎、公众号等内容创作。
- 支持给定 URL、PDF、JSON、RSS 等来源的信息搜集与汇总报告生成。
- 支持站内信息搜集和批量多任务信息搜集。
- 支持 arXiv 研究方向管理、论文拉取、星标、日报生成和历史日报查看。
- 支持模型 API 配置、提示词模板配置、文件上传解析、历史任务查看和 Markdown 导出。

## 技术栈

前端：

- Next.js 16
- React 19
- TypeScript
- Tailwind CSS

后端：

- FastAPI
- SQLAlchemy
- SQLite（MVP 默认）
- Pydantic Settings
- requests / BeautifulSoup / pypdf 等爬取与解析依赖

当前运行方式：

- 本地 Windows + WSL 脚本启动
- FastAPI 默认端口：`8000`
- Next.js 默认端口：`3000`
- 数据、上传、导出、日志默认保存在本地 `data/` 与 `logs/`

## 环境要求

推荐环境：

- Windows 10/11
- WSL2
- Python 3.14 或项目已有 `.venv`
- Node.js 20+
- npm

注意：

- `.env.local` 包含本地敏感配置，不应提交到 GitHub。
- 首次上传仓库前请确认 `.gitignore` 已生效。
- 当前 MVP 默认使用 SQLite；后续云原生阶段建议迁移到 PostgreSQL + Redis + Worker。

## 本地启动

### 方式一：Windows 批处理

在项目根目录双击：

```text
启动.bat
```

关闭服务：

```text
关闭.bat
```

### 方式二：WSL 命令

```bash
cd /mnt/d/Desktop/ChenSage_MVP1.0
bash start.sh
```

关闭：

```bash
cd /mnt/d/Desktop/ChenSage_MVP1.0
bash stop.sh --no-prompt
```

启动成功后访问：

- 前端页面：http://localhost:3000

## 基本使用流程

### 1. 配置模型

进入“模型设置”页面：

1. 新增 OpenAI-compatible 模型配置。
2. 填写 Base URL、模型名、API Key。
3. 设置默认模型。
4. 点击测试连接。

### 2. 配置提示词模板

进入“提示词模板”页面：

1. 选择任务类型，例如内容创作、信息搜集、arXiv 日报。
2. 填写系统提示词和用户提示词模板。
3. 可按细分类型设置默认模板。

### 3. 上传文件

进入“文件管理”页面：

1. 上传 PDF、DOCX、TXT、MD 等文件。
2. 后端自动解析文本。
3. 解析完成后可用于模拟面试或内容创作上下文。

### 4. 内容创作

进入“内容创作”页面：

1. 选择文体类型。
2. 填写主题、风格、素材等字段。
3. 生成大纲。
4. 基于大纲生成正文。
5. 可继续润色、扩写、缩写、改风格或平台适配。
6. 支持统一历史任务导出或本地 Markdown 导出兜底。

### 5. 模拟面试

进入“模拟面试”页面：

1. 选择已解析简历文件。
2. 输入目标岗位描述。
3. 生成简历分析。
4. 生成面试题。
5. 逐题提交回答并获得 AI 评价。
6. 自动生成完整面试复盘报告。
7. 支持导出复盘报告。

### 6. 信息搜集

进入“信息搜集”页面：

支持三类模式：

- 单组来源：输入一个 URL/PDF/JSON/RSS 来源，抓取后生成报告。
- 批量多任务：每个任务单独配置来源、模型、提示词，并行抓取后合并报告。
- 站内搜集：给定门户网站或站点入口，可选关键词和深度，自动发现相关页面并抓取。

流程：

1. 输入来源。
2. 开始抓取。
3. 检查右侧来源摘要和正文长度。
4. 选择可用来源。
5. 生成汇总报告。
6. 导出 Markdown。

### 7. arXiv 日报

进入“arXiv 日报”页面：

1. 新建研究方向。
2. 配置关键词、排除词、arXiv 分类。
3. 拉取论文。
4. 星标重要论文。
5. 选择日期、模型、模板。
6. 生成日报。
7. 查看历史日报并导出。

### 8. 历史任务与统一导出

进入“历史任务”页面：

- 支持按类型、状态、关键词筛选。
- 支持分页。
- 支持查看任务详情、输入、输出、模型、耗时、错误信息。
- 支持对已完成且有输出的任务进行统一 Markdown 导出。

## 当前限制

- 默认仍是 SQLite，不适合多人并发或生产部署。
- 后台长任务仍以本地进程为主，后续建议升级为 Redis 队列 + Worker。
- 文件存储仍是本地目录，后续建议抽象为 StorageService，并支持 MinIO/S3。
- 没有正式登录鉴权，`ENABLE_AUTH=false` 仅适合本地个人使用。
- 没有完整测试套件和 CI/CD。
- 部分复杂网页仍可能受反爬、JS 渲染或登录限制影响。

## 后续规划

建议下一阶段进入本地云原生化：

1. Docker Compose 本地服务编排。
2. API / Web / Worker 服务拆分。
3. SQLite 迁移 PostgreSQL。
4. Redis 任务队列。
5. MinIO 本地对象存储。
6. Alembic 数据库迁移。
7. 结构化日志和任务运行日志。
8. 可观测性与模型调用成本统计。
