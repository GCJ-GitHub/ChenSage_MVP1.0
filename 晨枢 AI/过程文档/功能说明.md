## 1. 任务执行引擎

### 功能概述

任务执行引擎是系统的核心调度器。用户创建任务后，引擎负责调度模型调用、管理任务状态流转、记录执行日志和耗时。

### 详细流程

```
用户创建任务 → 状态 = draft
    ↓
用户点击「开始执行」→ POST /tasks/{id}/run
    ↓
    ├─ 校验：是否有可用模型配置？
    ├─ 状态 = queued → running
    ├─ 后台线程启动 TaskExecutor.execute()
    │   ├─ 读取 task.input（用户输入）
    │   ├─ 读取关联文件文本（task_files → files.parsed_text）
    │   ├─ 查找 Prompt 模板（优先 DB 默认模板 → fallback 硬编码模板）
    │   ├─ 渲染模板（Jinja2 变量注入）
    │   ├─ 调用 ModelClient.generate() → DeepSeek API
    │   ├─ 成功：task.output = 结果, status = succeeded
    │   └─ 失败：task.error_message = 错误, status = failed
    └─ 记录 model_name / elapsed_ms / ModelCallLog
```

### 状态流转

```
draft → queued → running → succeeded
                          ↘ failed → queued (retry)
```

### 流式输出（SSE）

```
用户打开任务详情页 → GET /tasks/{id}/events
    ↓
TaskExecutor.execute_stream() 逐 token 推送
    ↓
前端通过 ReadableStream 接收 SSE 事件
    ↓
event: delta → 屏幕逐字追加显示
event: done  → 标记完成，清除加载状态
```

### 实现要点

| 文件 | 职责 |
|------|------|
| `models/task.py` | Task 表：type/status/input/output/model_name/elapsed_ms |
| `services/task_executor.py` | 执行调度、模板选择、模型调用、状态更新 |
| `services/model_client.py` | OpenAI 兼容接口封装（generate + stream + test） |
| `services/prompt_service.py` | Jinja2 模板渲染、9 套内置模板 |
| `api/tasks_api.py` | 7 个端点：CRUD + run + events + retry |
| `models/model_call_log.py` | 每次调用的 token 数、延迟、成本记录 |

### 关键逻辑

**模板选择优先级**（`_pick_template`）：
1. 用户显式选择 template_id → 直接用指定模板
2. 数据库中有 task_type + sub_type 的 is_default 模板 → 用数据库模板
3. 都没有 → 用 prompt_service 硬编码的 9 套模板

**Token 超限处理**：arXiv/研究等长报告任务在 `task.input` 里设 `override_max_tokens`，ModelClient 读取后覆盖默认的 4096。

**过期任务清理**：`mark_stale_tasks` 每 30 分钟扫描一次，把 `running`/`queued` 超时的任务标记为 failed。

## 2. 模型配置

### 功能概述

管理系统接入的 AI 模型。支持 OpenAI 兼容接口，每个模型可独立配置 Provider、Base URL、API Key、模型名、Temperature、Max Tokens、思考模式。

### 详细流程

```
用户进入「模型设置」页
    ↓ 点击「添加模型」
    ↓ 填写表单
    │   ├─ Provider: 服务商标识（如 deepseek）
    │   ├─ Base URL: API 地址
    │   ├─ API Key: 加密存储
    │   ├─ 模型名称: 模型 ID（如 deepseek-chat）
    │   ├─ 思考模式: auto / fast / deep
    │   ├─ Temperature: 0-2 滑块
    │   └─ Max Tokens: 输出上限
    ↓ 点击「测试连接」
    │   └─ POST /models/{id}/test → 调 /models 端点验证
    ↓ 保存 → 可被所有任务选择使用
```

### 快速预设

前端提供两个快捷预设按钮：
- **DeepSeek Chat**：快速模式，temp=0.7, tokens=4096
- **DeepSeek Reasoner**：深度思考，temp=1.0, tokens=8192

### 实现要点

| 文件 | 职责 |
|------|------|
| `models/model_config.py` | 含 extra_params(JSON) 存储温度/思考模式/支持模型列表 |
| `api/models_api.py` | 6 个端点：CRUD + test |
| `core/security.py` | Fernet 对称加密 API Key |
| `web/.../settings/models/page.tsx` | 表单 + 测试 + 预设按钮 |

### API Key 安全

- 存储：`api_key_encrypted` 字段用 `cryptography.fernet` 加密
- 展示：前端只显示脱敏值 `sk-x****xxxx`
- 日志：不会记录完整 Key

## 3. 文件上传与解析

### 功能概述

上传 PDF/DOCX/TXT/MD 文件，系统后台自动解析文本，供任务引用为 AI 上下文。

### 详细流程

```
用户在「文件管理」页上传文件
    ↓ POST /files（multipart/form-data）
    ├─ 校验类型（仅 .md .txt .pdf .docx）
    ├─ 校验大小（≤ 20MB）
    ├─ 保存到 data/uploads/
    ├─ 写入 files 表（parse_status = uploaded）
    └─ 启动后台解析线程
        ├─ registry.parse_file() 分发到对应解析器
        │   ├─ .pdf → pypdf 提取
        │   ├─ .docx → python-docx 提取
        │   └─ .md/.txt → 直接读取（多编码 fallback）
        ├─ 成功：parsed_text 写入, parse_status = parsed
        └─ 失败：parse_error 写入, parse_status = failed

用户在内容创作/简历面试中勾选文件
    ↓ task_files 表建立关联
    ↓ TaskExecutor._load_context() 读取 parsed_text
    ↓ 注入 Prompt 底部作为「参考资料」
```

### 解析器路由

```
文件扩展名 → registry.parse_file()
  .pdf    → pdf_parser.parse_pdf()
  .docx   → docx_parser.parse_docx()
  .md     → txt_parser.parse_text()
  .txt    → txt_parser.parse_text()
```

### 实现要点

| 文件 | 职责 |
|------|------|
| `services/parsers/registry.py` | 按扩展名分发 |
| `services/parsers/pdf_parser.py` | pypdf.PdfReader 逐页提取 |
| `services/parsers/docx_parser.py` | python-docx 段落+表格 |
| `services/parsers/txt_parser.py` | utf-8/gbk/gb2312/latin-1 多编码 fallback |
| `models/task_file.py` | 任务-文件多对多关联 |
| `api/files_api.py` | 5 个端点（上传/列表/详情/重解析/删除） |

## 5. 内容创作模块

### 功能概述

8 种文体全流程 AI 写作辅助：大纲 → 正文 → 改写。

### 8 种文体及专属表单

| 文体 | 专属字段 |
|------|----------|
| 论文草稿 | 研究主题、结构要求、参考资料、风格 |
| 专利草稿 | 技术方案名称、创新点、应用场景、技术细节 |
| 小说 | 题材/主题、人物设定、世界观、风格 |
| 剧本 | 题材/类型、角色设定、场景/冲突、风格 |
| 歌词 | 主题/情绪、押韵要求、结构、风格 |
| 小红书 | 主题、目标受众、口吻、标签 |
| 知乎 | 问题、核心观点、论据、风格 |
| 公众号 | 选题、读者画像、期望结构、风格 |

### 详细流程

```
选择文体 → 输入表单（各文体字段不同）
    ↓
点击「1. 生成大纲」
    ↓ POST /content/outline → 创建 content 任务（stage=outline）
    ↓ 后台线程执行 → 等待完成 → 前端轮询（2s 间隔，60 次）
    ↓ 大纲显示在可编辑 textarea
    ↓ 用户可手动修改大纲
    ↓
点击「2. 生成正文」
    ↓ POST /content/draft → 创建 content 任务（stage=draft）
    ↓ 后台线程执行 → 等待完成 → 前端轮询
    ↓ 正文显示在 Markdown 预览区
    ↓
点击改写按钮
    ↓ POST /content/rewrite（5 种类型）
    ├─ polish: 润色
    ├─ expand: 扩写
    ├─ shorten: 缩写
    ├─ change_style: 改风格
    └─ platform_adapt: 平台适配
    ↓ 新结果覆盖正文区
```

### 状态流转

```
用户点击按钮
    ↓
创建 Task (type=content, status=draft)
    ↓
后台执行 TaskExecutor.execute()
    ↓
status = running → TaskExecutor
    ↓
模型返回 → status = succeeded (output 写入)
    失败 → status = failed (error_message 写入)
    ↓
前端轮询 GET /tasks/{id}
    ↓ 检测到 succeeded → 停止轮询，渲染结果
```

### 提示词模板集成

- 内容创作页可以下拉选择「提示词模板」
- 模板按当前文体联动筛选（选"公众号"只看公众号模板）
- 选择了模板 → `template_id` 传给 API → TaskExecutor 用数据库模板替代硬编码模板

### 实现要点

| 文件 | 职责 |
|------|------|
| `api/content_api.py` | 3 个端点，创建任务 + 启动执行 |
| `schemas/content.py` | 请求体模型（含 template_id） |
| `web/app/content/page.tsx` | 8 种文体动态表单 + 大纲编辑 + Markdown 渲染 + 改写按钮 |
| `services/prompt_service.py` | content_outline / content_draft / content_rewrite 模板 |

## 6. 简历面试模块

### 功能概述

简历分析 → 岗位匹配 → 模拟面试 → 逐题评价 → 完整复盘报告。

### 详细流程

```
步骤 1: 上传简历 + 输入岗位 JD
    ↓ POST /interview/analyze
    ├─ 读取简历文件的 parsed_text
    ├─ 与 JD 拼接 → interview_analyze 模板 → 调 AI
    └─ 生成：优势 / 问题 / 修改建议 / 匹配度

步骤 2: 生成面试题
    ↓ POST /interview/{id}/questions
    ├─ 参数：题数(3-20)、难度(easy/medium/hard)、考察重点
    ├─ interview_questions 模板 → 调 AI
    └─ 输出题目列表

步骤 3: 逐题回答
    ↓ 左侧题目列表 + 右侧答题区
    ↓ 逐题输入回答 → POST /interview/{id}/answers
    ├─ interview_answer 模板（问题 + 回答 + JD） → 调 AI
    └─ 每题即时评价（表达/逻辑/专业性）

步骤 4: 生成复盘报告
    ↓ 全部回答后 → POST /interview/{id}/review
    ├─ 汇总所有回答记录 → interview_review 模板 → 调 AI
    └─ 最终复盘：总体优势 / 不足 / 改进建议 / 下一步准备
```

### 面试记录累积

每次提交回答后 → `POST /interview/{id}/save-result` → 把结果追加到父任务的 `input.interview_results` 字段 → 复盘时可读取全部记录。

### 实现要点

| 文件 | 职责 |
|------|------|
| `api/interview_api.py` | 6 个端点（含 template_id 支持） |
| `schemas/interview.py` | 4 个请求 Schema |
| `web/app/interview/page.tsx` | 4 步进度条 + 题目切换 + 评价展示 |
| `services/prompt_service.py` | interview_analyze / questions / answer / review 模板 |

## 7. 信息搜集模块

### 功能概述

用户输入 URL 列表 → 系统抓取网页正文 → 去重 → AI 生成汇总报告。

### 详细流程

```
用户输入 URL（每行一个）
    ↓ POST /research/tasks
    ├─ 解析 URL 列表
    ├─ 创建 Task (type=research, status=queued)
    └─ 启动后台线程 _run_fetch()
        ├─ 逐 URL 调用 crawler.fetch_url()
        │   ├─ requests.get() + BeautifulSoup 提取正文
        │   ├─ 去除 script/style/nav/footer/aside
        │   └─ 截断到 8000 字
        ├─ 每个结果写入 research_sources 表
        │   └─ fetch_status = succeeded / failed
        └─ 全部完成后 task.status = succeeded

前端轮询 GET /research/tasks/{id}/sources
    ↓ 展示每个来源的状态/标题/正文预览

用户点击「生成报告」
    ↓ POST /research/tasks/{id}/report
    ├─ 拼接所有成功来源的正文 → source_text
    ├─ 截断到 10000 字防溢出
    ├─ 创建新 Task (stage=report, override_max_tokens=8192)
    ├─ TaskExecutor 执行 → research_summarize 模板
    └─ 前端轮询等待 → 展示 Markdown 报告
```

### 抓取器特性

| 能力 | 说明 |
|------|------|
| UA 伪装 | Chrome 120 浏览器标识 |
| 超时控制 | 15 秒单页超时 |
| HTML 清洗 | 去 script/style/nav/footer |
| 正文截断 | 8000 字防止 Token 溢出 |
| 单页失败 | 不影响其他 URL |
| 重抓支持 | `POST /research/sources/{id}/refetch` |

### 实现要点

| 文件 | 职责 |
|------|------|
| `services/crawler.py` | 网页抓取 + HTML 清洗 |
| `api/research_api.py` | 6 个端点 |
| `models/research_source.py` | 来源元数据（URL/标题/正文/状态） |
| `web/app/research/page.tsx` | URL 输入 + 来源列表 + 报告展示 |

## 8. arXiv 论文日报

### 功能概述

配置研究方向 → 从 arXiv API 拉取最新论文 → AI 生成中文日报简报。

### 详细流程

```
步骤 1: 创建研究方向
    ↓ POST /arxiv/directions
    ├─ 名称：如"AI Agent"
    ├─ 关键词：["agent", "multi-agent"]
    ├─ arXiv 分类：["cs.AI", "cs.CL"]
    └─ 排除词：["survey"]

步骤 2: 拉取论文
    ↓ POST /arxiv/directions/{id}/fetch
    ├─ build_query() 构造搜索表达式
    │   └─ (cat:cs.AI)+AND+(all:"agent"+AND+all:"multi-agent")+ANDNOT+(all:"survey")
    ├─ 请求 http://export.arxiv.org/api/query（Atom XML）
    ├─ 解析 XML → 提取标题/作者/摘要/链接/分类
    ├─ 按 direction_id + arxiv_id 去重
    └─ 新论文写入 arxiv_papers 表

步骤 3: 论文管理
    └─ GET /arxiv/papers 列表（支持 direction/date/starred 筛选）
    └─ PATCH /arxiv/papers/{id} 标记收藏（is_starred）

步骤 4: 生成日报
    ↓ POST /arxiv/directions/{id}/daily-report
    ├─ 取最近 max_papers 篇论文
    ├─ 拼接成 paper_text（每篇 500 字摘要）
    ├─ 总长截断到 12000 字
    ├─ 创建 Task (type=arxiv_daily, override_max_tokens=16384)
    ├─ TaskExecutor 执行 → arxiv_daily 模板 → 调 AI
    └─ 前端轮询 → 显示中文日报
```

### 状态流转

```
创建方向 → 拉取论文
    ↓
arxiv_papers 表新增记录
    ↓
用户点击「生成日报」
    ↓
创建 Task (type=arxiv_daily)
    ↓
TaskExecutor.execute()
    ↓
task.status: queued → running → succeeded → output 写入日报内容
    ↓
同时自动保存 arxiv_daily_report 记录
```

### 实现要点

| 文件 | 职责 |
|------|------|
| `services/arxiv_service.py` | arXiv API 调用 + Atom XML 解析 |
| `api/arxiv_api.py` | 7 个端点 |
| `models/arxiv_direction.py` | 方向配置（keywords/categories JSON） |
| `models/arxiv_paper.py` | 论文元数据 + 收藏标记 |
| `models/arxiv_daily_report.py` | 生成的历史日报 |
| `web/app/arxiv/page.tsx` | 四栏布局：方向/论文/报告 |

## 9. 历史任务与导出

### 功能概述

完成任务列表筛选、搜索查看，以及将任务结果导出为 Markdown 文件。

### 任务列表

```
GET /tasks?type=content&status=succeeded&keyword=AI
    ↓ 返回分页列表
    ├─ 筛选维度：type / status / keyword
    ├─ 表格列：标题 / 类型(中文) / 状态 / 模型 / 耗时 / 时间
    └─ 点击进入 /tasks/{id} 详情页
```

### 任务详情页

```
GET /tasks/{id}
    ↓ 显示任务完整信息
    ├─ 基础信息：标题/类型/状态/模型/耗时/时间
    ├─ 关联文件列表
    ├─ 输出结果（Markdown 渲染）
    ├─ 操作按钮
    │   ├─ 开始执行（draft 状态）
    │   ├─ 重试（failed 状态）
    │   ├─ 重新生成（succeeded 状态）
    │   └─ 导出（任意状态，有 output 即可）
    └─ 模型选择器（可在执行前切换模型）
```

### Markdown 导出

```
用户点击「导出」
    ↓ POST /export/tasks/{id}
    ├─ 拼接 Markdown 内容
    │   ├─ # 标题
    │   ├─ 元数据（ID/类型/模型/耗时/时间）
    │   ├─ ## 输入（JSON 格式）
    │   └─ ## 输出（原文）
    ├─ 写入 data/exports/ 目录
    ├─ 记录到 exports 表
    └─ 返回下载 URL
    ↓ 前端自动触发浏览器下载 .md 文件
```

### 实现要点

| 文件 | 职责 |
|------|------|
| `api/tasks_api.py` | 任务 CRUD + 筛选搜索 |
| `api/export_api.py` | Markdown 生成 + FileResponse 下载 |
| `models/export_record.py` | 导出记录（文件路径/文件名/时间） |
| `web/app/tasks/page.tsx` | 筛选器 + 任务表格 |
| `web/app/tasks/[id]/page.tsx` | 详情展示 + SSE 流式 + 导出按钮 |
