## 1. 文档目的

本文档用于明确晨枢 AI 在 MVP 阶段到底做哪些功能、哪些功能必须先做、哪些功能应该后做，以及每类功能的验收目标、依赖关系和阶段边界。

这份文档的作用不是重复 PRD，而是把 PRD 中较大的需求收敛成一份可以直接指导原型设计、开发排期和任务拆分的功能优先级清单。

## 2. MVP 阶段定义

晨枢 AI 的 MVP 阶段目标是：先做出一个个人可用、可持续使用、能形成真实闭环的 AI 工作台，而不是一次性覆盖所有 AI 能力。

MVP 必须满足以下原则：

1. 可以稳定使用。
2. 可以完成至少 3 到 4 个高频任务闭环。
3. 可以保存历史任务和结果。
4. 可以通过配置 API 实际跑起来。
5. 后续能扩展到定时任务、知识库、本地模型和上线版本。

## 3. 优先级定义

### 3.1 P0

P0 为 MVP 必做项。

没有这些功能，平台不能形成基本闭环，或者用户虽然能进入页面，但无法真正完成任务。

### 3.2 P1

P1 为 MVP 后优先补齐项。

这些功能会显著提升体验、自动化能力和长期使用价值，但不会阻塞第一版上线自用。

### 3.3 P2

P2 为中后期增强项。

这些功能关系到本地模型、RAG、产品化、多用户、商业化和规模化，但不应挤占 MVP 的交付节奏。

## 4. MVP 成功标准

MVP 完成后，至少应做到：

1. 用户可以在本地或私有环境跑起来。
2. 用户可以配置模型 API 并成功发起任务。
3. 用户可以上传资料并将资料用于任务上下文。
4. 用户可以完成一次简历分析和模拟面试复盘。
5. 用户可以完成一次论文、专利或创意写作任务。
6. 用户可以完成一次网页信息搜集与汇总。
7. 用户可以完成一次 arXiv 论文日报生成。
8. 用户可以查看历史任务并导出结果。

## 6. P0 功能清单

### 6.1 基础工作台

目标：

提供统一任务入口，让用户进入系统后能快速开始任务、查看最近结果和继续未完成工作。

功能项：

- 首页工作台。
- 常用任务入口。
- 最近任务列表。
- 任务状态展示。
- 快捷进入设置页。

验收口径：

- 用户进入系统后可以在 3 次点击内开始任一核心任务。
- 最近任务按时间倒序可见。
- 未配置模型时首页有明显提示。

依赖：

- 任务系统。
- 模型配置。

优先级：P0

### 6.2 模型 API 配置

目标：

支持用户配置可用模型，使全站任务能通过统一接口调用大模型。

功能项：

- API Provider 配置。
- API Key 配置。
- Base URL 配置。
- 模型名称配置。
- 默认模型设置。
- 模型连接测试。

验收口径：

- 用户完成配置后可以发起一次成功测试。
- 配置错误时能返回明确错误信息。
- API Key 不明文展示。

依赖：

- 基础设置页。

优先级：P0

### 6.3 文件上传与解析

目标：

支持用户上传简历、论文资料、写作素材等文件，并将内容转换为可供模型使用的文本上下文。

功能项：

- 文件上传。
- 文件列表。
- 文件删除。
- 解析状态显示。
- 解析文本预览。
- 任务中选择文件作为上下文。

支持格式：

- Markdown。
- TXT。
- PDF。
- DOCX。

验收口径：

- 文件上传成功后可在列表中看到。
- 解析成功后可被任务引用。
- 解析失败时有明确错误提示。

依赖：

- 文件存储。
- 文档解析器。

优先级：P0

### 6.4 通用任务系统

目标：

统一承载各类 AI 任务，保存输入、状态、输出和错误记录。

功能项：

- 新建任务。
- 任务类型选择。
- 任务名称。
- 输入参数保存。
- 执行状态展示。
- 输出结果保存。
- 失败记录保存。
- 历史任务查看。
- 重试或重新生成。

任务状态：

- 草稿。
- 执行中。
- 已完成。
- 已失败。

验收口径：

- 每个任务有唯一 ID。
- 每个任务都能保存输入和输出。
- 失败任务也能在历史中查看。

依赖：

- 数据存储。
- 模型调用服务。

优先级：P0

### 6.5 简历分析与模拟面试

目标：

完成一个完整的求职辅助闭环，从简历诊断到岗位匹配，再到面试模拟和复盘。

功能项：

- 上传简历。
- 输入岗位 JD。
- 简历结构分析。
- 优势提取。
- 问题诊断。
- 简历优化建议。
- 岗位匹配度分析。
- 面试问题生成。
- 用户回答输入。
- 回答评价。
- 面试复盘报告。

验收口径：

- 系统能识别简历中的教育、经历、项目和技能。
- 系统能根据岗位生成有针对性的面试问题。
- 复盘报告至少包含优势、不足、改进建议和准备方向。

依赖：

- 文件上传与解析。
- 通用任务系统。
- 模型调用服务。

优先级：P0

### 6.6 内容创作模块

目标：

支持多个高频写作场景，形成统一的内容生成和改写闭环。

功能项：

- 创作类型选择。
- 主题输入。
- 风格输入。
- 篇幅输入。
- 素材输入。
- 大纲生成。
- 正文生成。
- 润色。
- 扩写。
- 缩写。
- 改风格。

首版支持类型：

- 论文草稿。
- 专利草稿。
- 小说。
- 剧本。
- 歌词。
- 小红书文案。
- 知乎回答。
- 公众号推文。

验收口径：

- 至少支持 8 种内容类型。
- 每种类型都能产出结构化初稿。
- 用户可以基于当前结果继续生成下一轮内容。

依赖：

- 通用任务系统。
- 模型调用服务。

优先级：P0

### 6.7 信息搜集与汇总

目标：

支持从 URL 或关键词搜集信息，并生成结构化摘要和汇总报告。

功能项：

- 输入 URL。
- 输入关键词。
- 抓取网页内容。
- 提取标题、正文、来源链接。
- 内容去重。
- 摘要生成。
- 汇总报告生成。

验收口径：

- 报告中保留来源链接。
- 系统能处理多个来源并输出汇总。
- 某个来源失败时，其它来源仍可继续处理。

依赖：

- 抓取工具。
- 通用任务系统。
- 模型调用服务。

优先级：P0

### 6.8 arXiv 论文日报

目标：

支持研究方向配置和最新论文日报生成，形成可长期复用的研究跟踪入口。

功能项：

- 研究方向配置。
- 关键词配置。
- arXiv 分类配置。
- 手动拉取论文。
- 论文筛选。
- 中文摘要生成。
- 贡献点提取。
- 推荐精读标记。
- 日报保存。

验收口径：

- 用户至少能配置一个研究方向。
- 每篇论文展示标题、作者、链接、发布时间和摘要。
- 日报可以手动生成并保存在历史中。

依赖：

- 外部论文源接入。
- 通用任务系统。
- 模型调用服务。

优先级：P0

## 7. P1 功能清单

### 7.1 Markdown 导出

目标：

允许用户将任务结果以标准 Markdown 形式导出，便于继续编辑和归档。

功能项：

- 导出 Markdown。
- 一键复制结果。
- 保留标题和结构。

优先级：P1

### 7.2 结果版本管理

目标：

让用户保存多次生成结果，便于比较和回退。

功能项：

- 保存版本。
- 版本命名。
- 版本时间记录。
- 版本回看。

优先级：P1

### 7.3 定时任务

目标：

让系统自动执行周期性任务，例如每日 arXiv 日报、每日资讯汇总和股票信息简报。

功能项：

- 新建定时任务。
- 配置执行频率。
- 启用和暂停。
- 最近执行记录。
- 失败重试。

优先级：P1

### 7.4 股票研究辅助

目标：

在信息搜集能力基础上，进一步支持股票池管理、行情资讯整理和研究辅助输出。

功能项：

- 股票池配置。
- 新闻和公告抓取。
- 基础信息汇总。
- 风险提示。
- 研究报告生成。

边界说明：

- 仅作研究辅助。
- 不支持自动交易。
- 不承诺投资收益。

优先级：P1

### 7.5 轻量知识库

目标：

支持把历史资料、论文、文档和任务结果沉淀为可检索内容。

功能项：

- 文档入库。
- 基础检索。
- 任务中引用知识片段。
- 结果与资料关联。

优先级：P1

## 8. P2 功能清单

### 8.1 多模型路由

目标：

根据任务复杂度、成本和隐私等级选择不同模型。

功能项：

- 任务级模型选择。
- 默认路由规则。
- 高低成本模型分流。

优先级：P2

### 8.2 本地模型接入

目标：

为高隐私、低成本或离线场景提供本地模型能力。

功能项：

- Ollama 接入。
- OpenAI 兼容本地接口接入。
- 本地模型健康检查。
- 本地模型与云端模型切换。

优先级：P2

### 8.3 RAG 检索增强

目标：

通过向量检索提升长文档、多资料和固定知识场景下的生成质量。

功能项：

- 文档切片。
- 向量化。
- 检索召回。
- 引用片段注入 Prompt。

优先级：P2

### 8.4 多用户与权限

目标：

支持后期上线时的账号体系和数据隔离。

功能项：

- 注册登录。
- 用户空间隔离。
- 权限控制。
- 管理后台。

优先级：P2

### 8.5 成本统计与监控

目标：

帮助用户或后期平台运营者了解模型调用成本和系统使用情况。

功能项：

- 调用次数统计。
- Token 消耗统计。
- 模型成本估算。
- 错误率统计。

优先级：P2

## 9. 首版建议范围

如果希望尽快交付一个能真实使用的版本，首版建议只做以下内容：

1. 工作台首页。
2. 模型 API 设置页。
3. 文件上传与解析。
4. 通用任务系统。
5. 简历分析与模拟面试。
6. 内容创作模块。
7. 信息搜集与汇总。
8. arXiv 论文日报。
9. 历史任务页。
10. 基础 Markdown 导出。

这意味着：

- `P0` 全部纳入。
- `P1` 中只建议把 `Markdown 导出` 尽量提前到首版。
- 其它 `P1` 和 `P2` 暂缓。

## 10. 建议开发顺序

为了降低风险并尽快形成闭环，建议按以下顺序开发：

1. 模型 API 配置。
2. 通用任务系统。
3. 文件上传与解析。
4. 工作台首页与任务详情页。
5. 内容创作模块。
6. 简历分析与模拟面试。
7. 信息搜集与汇总。
8. arXiv 论文日报。
9. 历史任务与导出能力。

原因：

- 前 4 项是所有能力的基础。
- 内容创作最容易先跑通闭环。
- 简历模块是强场景功能，适合尽早验证效果。
- 信息搜集和 arXiv 日报对工具链要求更高，适合基础模块稳定后接入。

## 11. 功能拆分建议

为了便于后续排期，可以把功能拆成以下几类开发任务：

### 11.1 页面层

- 工作台首页。
- 任务创建页。
- 任务详情页。
- 文件管理页。
- 模型设置页。
- 简历面试页。
- 内容创作页。
- 信息搜集页。
- arXiv 日报页。

### 11.2 服务层

- 模型调用服务。
- 文件解析服务。
- 任务执行服务。
- 网页抓取服务。
- arXiv 拉取服务。

### 11.3 数据层

- 任务表。
- 文件表。
- 模型配置表。
- arXiv 方向表。
- arXiv 论文表。
- 任务结果或版本表。

## 12. 明确不纳入 MVP 的内容

以下内容本轮不应纳入 MVP：

- 商业化支付。
- 多租户团队协作。
- 自动交易或下单。
- 专业量化分析。
- 完整微调平台。
- 大规模爬虫集群。
- 复杂审批流。
- 专业法律审查能力。
- 自动生成不可核验的结论并作为权威输出。

## 13. 交付验收清单

这份文档对应的 MVP 功能清单，在后续验收时应至少逐条确认：

- 可以配置并测试模型 API。
- 可以上传和解析文件。
- 可以创建和保存任务。
- 可以查看任务状态和历史。
- 可以完成简历分析与模拟面试。
- 可以完成内容创作任务。
- 可以完成网页信息搜集与汇总。
- 可以生成 arXiv 论文日报。
- 可以导出基础 Markdown 结果。
